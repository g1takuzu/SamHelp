# SamHelp ↔ amoCRM

## Текущая модель синхронизации

- Каждый пользователь SamHelp подключает свой аккаунт amoCRM через OAuth.
- SamHelp ищет контакт в amoCRM по точному нормализованному номеру телефона.
- Для найденного контакта SamHelp получает связанную сделку, воронку и статус.
- **amoCRM — единственный источник статуса.** В SamHelp статус отображается, но не редактируется и никогда не отправляется обратно в amoCRM.
- Если совпадение по телефону не найдено, SamHelp показывает «Не найден в amoCRM».
- Если к контакту привязано несколько сделок, выбирается самая недавно обновлённая.
- Изменения статусов поступают через webhook amoCRM, если аккаунт разрешает регистрацию webhook. Если прав администратора нет, остаётся резервное обновление по расписанию в SamHelp.
- OAuth access/refresh tokens и ключи интеграции хранятся только в зашифрованном виде на сервере.

## Приватность контактов и общие данные

- Контакты хранятся в `private_contacts` с `user_id`.
- RLS проверяет `auth.uid() = user_id` для чтения, создания, изменения и удаления. Роль администратора не даёт доступа к чужим контактам.
- Общие воронки, статусы, общие шаблоны и параметры хранятся отдельно в `shared_app_config`.
- Общие таблицы и программы хранятся в `shared_links`.
- Изменения передаются через Supabase Realtime; периодическая проверка остаётся резервом.

## SQL-миграции

В Supabase SQL Editor последовательно применить миграции из репозитория:

1. `202611180001_amo_integration.sql`
2. `202611180002_amo_external_credentials.sql`
3. `202611180003_private_contacts_and_shared_config.sql`
4. `202611180004_amo_webhooks.sql`

Предыдущие миграции `202611120001`–`202611120005` должны быть уже применены для Auth, ролей и общих ссылок.

## Secrets Supabase

В Supabase Dashboard → Edge Functions → Secrets проверить:

- `AMO_REDIRECT_URI` — точный callback URL: `https://<project-ref>.supabase.co/functions/v1/amo-oauth-callback`
- `AMO_TOKEN_ENCRYPTION_KEY` — Base64 от случайных 32 байт для AES-GCM.

Системные `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` предоставляет среда Supabase Functions. Их нельзя добавлять в Electron или GitHub.

## Edge Functions

Развернуть функции:

| Функция | JWT |
|---|---|
| `amo-oauth-start` | включён |
| `amo-oauth-secrets` | выключен |
| `amo-oauth-callback` | выключен |
| `amo-connection-status` | включён |
| `amo-contact-status` | включён |
| `amo-webhook` | выключен, проверяет секретный URL-ключ |

Интерфейс SamHelp содержит кнопку «Подключить amoCRM». Она запускает внешний OAuth-процесс; пользователь подтверждает доступ в своём аккаунте.

## Ограничения прав amoCRM

Создание интеграции и регистрация webhook могут требовать прав администратора аккаунта amoCRM. SamHelp не обходит эти ограничения. Если пользователь не является администратором, подключение должен подтвердить администратор аккаунта. Если webhook нельзя зарегистрировать, чтение статуса продолжает работать при периодической проверке.

## Проверка перед сборкой EXE

1. Применить миграции.
2. Развернуть все перечисленные Edge Functions.
3. Проверить Secrets.
4. Войти в SamHelp и подключить тестовый аккаунт amoCRM.
5. Создать тестовый контакт в SamHelp с номером, который точно существует в amoCRM.
6. Убедиться, что отображается статус из amoCRM.
7. Изменить статус сделки непосредственно в amoCRM и проверить обновление SamHelp.
8. Убедиться, что ручное изменение статуса в SamHelp невозможно и не отправляет запросы изменения сделки в amoCRM.
9. Войти под вторым пользователем и проверить, что первый пользователь не видит его контакты.
